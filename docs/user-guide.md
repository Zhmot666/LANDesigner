# Руководство пользователя LanDesigner

LanDesigner — десктопное приложение инженера ЛВС. Один проект = один файл **`.lanproj`**. Данные можно вести полностью офлайн; при необходимости проект синхронизируется с сервером (см. [sync-server.md](sync-server.md)).

---

## 1. Интерфейс

```
┌─────────────────────────────────────────────────────────────┐
│ Файл  Правка  Синхронизация  Инструменты                    │
├──────────┬──────────────────────────────┬───────────────────┤
│ Дерево   │  Вкладки: Схема | План | …   │ Карточка объекта  │
│ площадки │  (основная рабочая область)  │ (контекстная)     │
├──────────┴──────────────────────────────┴───────────────────┤
│ Статус: путь к файлу | состояние sync                       │
└─────────────────────────────────────────────────────────────┘
```

### Дерево слева

Иерархия **площадка → здание → этаж → комната → шкаф**. Фильтрует инвентарь по выбранному узлу. Поиск: **Ctrl+K**.

### Вкладки

| Вкладка | Назначение |
|---------|------------|
| **Схема** | Логическая топология: узлы, связи, кабели |
| **План** | План этажа: подложка, маркеры устройств, трассы кабелей |
| **Стойка** | Front/Rear монтаж в шкафу, drag по U |
| **Каталог** | Справочник **типов** устройств (отдельно от инвентаря) |
| **Инвентарь** | Устройства, порты, кабели, VLAN, IP, LAG, VRF, vSwitch |
| **Отчёты** | Проверки проекта и табличные отчёты |

### Карточка объекта

Справа (на схеме/плане) или внизу (на инвентаре) — свойства выбранного **проекта**, **здания**, **устройства** или **шкафа**.

---

## 2. Первый проект

1. **Файл → Новый** — укажите имя и путь `.lanproj`.
2. В дереве: ПКМ на площадке → добавить **здание**, **этаж**, **комнату**, **шкаф**.
3. **Каталог** (или **Инвентарь → типы**): создайте **тип устройства** с группами портов.
4. **Инвентарь → Устройства**: добавьте экземпляр, укажите hostname, комнату/шкаф.
5. **Файл → Сохранить** (`Ctrl+S`).

Assets планов этажа хранятся в каталоге `<имя>.lanproj.assets/` рядом с проектом.

---

## 3. Типы устройств

Тип задаёт **роль** и **шаблон портов** для новых устройств.

### Диалог типа

- **Производитель / модель / роль**
- **Группы портов:** префикс имени, количество, стартовый номер, среда (медь/оптика), скорость, сторона (Front/Rear для патч-панелей)
- Кнопки: **Без портов** (ИБП, PDU — только CMDB), **Патч-панель 24/48**

Изменение шаблона **не пересоздаёт** порты у уже существующих устройств — только у новых.

### Каталог и пресеты

- **Инструменты → Тип из каталога** — готовые шаблоны (коммутатор, сервер, патч-панель…).
- **Каталог → Экспорт/Импорт пресета** — файл `.ldtypes` для обмена между проектами (merge по vendor+model).

---

## 4. Инвентарь

### Устройства

Карточка: серийный №, инв. №, комната, шкаф, юниты (U), высота в U.  
Роли **гипервизор** и **ВМ** — см. раздел 8.

Удаление устройства удаляет его порты и разрывает связанные кабели.

### Порты

- Список портов выбранного устройства.
- **Добавить порт** — вручную (в т.ч. к устройству без шаблонных портов).
- **Сеть порта** — Access/Trunk, VLAN, IP.
- **Свойства порта** — имя, MAC, скорость, среда.

### Кабели

**Соединить порты кабелем:** выберите два порта → метка, вид (медь/оптика/DAC), категория, длина, цвет, назначение.

Путь через патч-панель отображается в отчёте и подсказках.

### VLAN и VRF

- **VLAN** — справочник с ID 1–4094; привязка access/tagged на порту.
- **VRF** — имя и RD; IP уникален в пределах VRF (или глобально без VRF).

### LAG

Группа портов одного устройства: Active-Backup / LACP / Static. IP можно назначить на LAG.

---

## 5. Схема топологии

- Узлы соответствуют устройствам; связи — кабелям.
- Перетаскивание узлов, **snap к сетке**, **автораскладка**.
- На линках: VLAN, скорость; **легенда ролей**.
- Групповое выделение и перемещение — **одна команда Undo**.
- Синхронизация выделения: схема ↔ дерево ↔ карточка.

Устройство без узла на схеме — **предупреждение** на вкладке «Отчёты».

---

## 6. План этажа

1. Выберите **этаж** в дереве или на вкладке «План».
2. Импортируйте **подложку** (изображение плана).
3. Разместите **маркеры** устройств комнаты; задайте **масштаб** (м/пиксель).
4. Режим **Трасса** — полилинии для прокладки; привязка к кабелю и запись длины.

Групповый drag маркеров — Undo одной командой. Легенда ролей на плане.

---

## 7. Стойка (шкаф)

Вкладка **Стойка** при выборе шкафа в дереве:

- **Front / Rear** стороны, свободные U подсвечены.
- **Drag & drop** монтажа из комнаты; метка U при перетаскивании.
- ПКМ: снять с монтажа, изменить высоту в U.
- Undo/Redo для операций стойки.

Отчёт **«Шкафы / юниты»** — заполнение, список монтажа, свободные юниты.

---

## 8. Виртуализация

### Гипервизор и ВМ

- Роль **HYPERVISOR** — физический хост ESXi/Hyper-V и т.п.
- Роль **VIRTUAL_MACHINE** — при создании обязателен **хост**; ВМ наследует комнату хоста, **не** монтируется в шкаф.

### vSwitch и Port Group

На гипервизоре: **vSwitch**, **Port Group** (+ VLAN), uplink на NIC.  
vNIC ВМ привязывается к Port Group или напрямую к NIC хоста (`vNIC→NIC`).

Вкладка **vSwitch** в инвентаре при выборе гипервизора.

---

## 9. Патч-панели

Тип с ролью **PATCH_PANEL** и парами **Front ↔ Rear**:

- Матрица пар, статус (свободна / занята / частично).
- Быстрое создание кабеля с порта (двойной клик в матрице).
- Валидация: кабель только с одной стороны пары — предупреждение.

---

## 10. Отчёты и проверки

Вкладка **Отчёты**:

### Проверки

Автозапуск при открытии. Примеры правил:

| Уровень | Примеры |
|---------|---------|
| Ошибка | Дублирующий IP |
| Предупреждение | Кабель без метки, устройство не на схеме/плане, ВМ без хоста |
| Инфо | Занят без кабеля, vSwitch без uplink |

### Отчёты

| Тип | Содержание |
|-----|------------|
| Реестр оборудования | Hostname, серийник, роль, комната, шкаф, U |
| Порт-матрица | Все порты, VLAN, IP, связь |
| Кабели | Метки, длина, цвет, путь через PP |
| VLAN map | Access / Tagged порты |
| VRF / IP scope | Адреса по VRF |
| Шкафы / юниты | Заполнение, монтаж |

Экспорт: **CSV**, **PDF** (A4 landscape), **Печать**.

## 11. Файл и обмен данными

| Меню | Действие |
|------|----------|
| **Файл → Экспорт CSV** | Весь проект в текстовый CSV (свой формат) |
| **Файл → Импорт CSV** | Замена данных открытой сессии |
| **Файл → Создать снимок** | Копия `.lanproj` с меткой времени |
| **Файл → Восстановить снимок** | Откат к сохранённому снимку |
| **Файл → Свойства проекта** | Имя, revision, origin |

CSV начинается с `#LANDESIGNER_CSV;version=1`. Чужие форматы (NetBox, 1С) не поддерживаются.

---

## 12. Правка (Undo / Redo)

**Ctrl+Z** / **Ctrl+Y** — отмена и повтор для операций на **схеме**, **плане**, **стойке** (перемещения, трассы, монтаж и т.д.).

Не все действия в таблицах инвентаря попадают в общий стек — после крупных правок сохраняйте проект.

---

## 13. Типовые сценарии

### Новая стойка в комнате

1. Комната → шкаф (42U).
2. Типы: коммутатор, патч-панель 48, сервер.
3. Устройства + монтаж на **Стойке**.
4. Кабели: patch panel ↔ switch ↔ server.
5. VLAN/IP на uplink и серверных портах.
6. Узлы на **Схеме**, маркеры на **Плане**.

### ИБП без портов

1. Тип: роль **Прочее**, кнопка **Без портов**.
2. Устройство: serial, инв. №, шкаф U40–41.
3. Отчёт «Реестр оборудования» — учёт без порт-матрицы.

### Совместная работа

1. Поднять [sync-server](sync-server.md).
2. **Опубликовать** локальный проект.
3. Коллега **клонирует** или делает **Pull**.
4. При конфликте revision — диалог с diff.

---

## 14. Ограничения

- Один открытый проект в окне.
- Схема рассчитана на порядка **1–2 тыс.** объектов scene.
- SNMP/discovery, realtime-коллаборация, 3D-стойки — не реализованы.
- Коллаборация — **батчами** (Push/Pull), не одновременное редактирование.
